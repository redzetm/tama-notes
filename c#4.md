# 何も知らない人向けC#.net 4 — 継承・例外・コレクション 編

この巻の範囲：

## 継承

### 継承とは

継承は、すでにあるクラスの共通部分を受け継いで、新しいクラスを作る仕組みです。  
ここでは「もとになる設計図を引き継いで、必要な分だけ足す」と考えれば大丈夫です。

```csharp
using System;

class Animal
{
    public string Name;
}

class Dog : Animal
{
}

class Program
{
    static void Main(string[] args)
    {
        Console.WriteLine("Dog は Animal を引き継いでいます");
    }
}
```

出力イメージ：

```text
Dog は Animal を引き継いでいます
```

### 親クラスと子クラス

もとになるクラスを親クラス、引き継いで作るクラスを子クラスと呼ぶことがあります。  
ここでは「もと」と「引き継いだ側」と考えれば十分です。

```csharp
using System;

class Animal
{
    public string Name;
}

class Cat : Animal
{
}

class Program
{
    static void Main(string[] args)
    {
        Cat cat = new Cat();
        cat.Name = "ミケ";

        Console.WriteLine(cat.Name);
    }
}
```

出力イメージ：

```text
ミケ
```

### 引き継いだフィールドを使う

子クラスは、親クラスの公開されている値をそのまま使えます。

```csharp
using System;

class Vehicle
{
    public string Maker;
}

class Car : Vehicle
{
}

class Program
{
    static void Main(string[] args)
    {
        Car car = new Car();
        car.Maker = "ABC 自動車";

        Console.WriteLine(car.Maker);
    }
}
```

出力イメージ：

```text
ABC 自動車
```

### 引き継いだメソッドを使う

親クラスのメソッドも、子クラスから使えます。

```csharp
using System;

class Animal
{
    public void Sleep()
    {
        Console.WriteLine("眠ります");
    }
}

class Dog : Animal
{
}

class Program
{
    static void Main(string[] args)
    {
        Dog dog = new Dog();
        dog.Sleep();
    }
}
```

出力イメージ：

```text
眠ります
```

### 子クラスに新しい機能を足す

子クラスは、引き継ぐだけでなく、自分だけの値やメソッドも持てます。

```csharp
using System;

class Animal
{
    public string Name;
}

class Dog : Animal
{
    public void Bark()
    {
        Console.WriteLine("ワンワン");
    }
}

class Program
{
    static void Main(string[] args)
    {
        Dog dog = new Dog();
        dog.Name = "ポチ";

        Console.WriteLine(dog.Name);
        dog.Bark();
    }
}
```

出力イメージ：

```text
ポチ
ワンワン
```

### 共通部分を親にまとめる

似たクラスが複数あるとき、共通の値やメソッドを親クラスに置くと見通しがよくなります。

```csharp
using System;

class Employee
{
    public string Name;

    public void ShowName()
    {
        Console.WriteLine(Name);
    }
}

class Engineer : Employee
{
}

class Designer : Employee
{
}

class Program
{
    static void Main(string[] args)
    {
        Engineer engineer = new Engineer();
        engineer.Name = "佐々木";

        Designer designer = new Designer();
        designer.Name = "井上";

        engineer.ShowName();
        designer.ShowName();
    }
}
```

出力イメージ：

```text
佐々木
井上
```

### base

親クラス側のコンストラクタやメソッドをはっきり使いたいときに `base` を使います。  
ここでは「親側を指す目印」と考えれば大丈夫です。

```csharp
using System;

class Person
{
    public string Name;

    public Person(string name)
    {
        Name = name;
    }
}

class Student : Person
{
    public Student(string name) : base(name)
    {
    }
}

class Program
{
    static void Main(string[] args)
    {
        Student student = new Student("中村");
        Console.WriteLine(student.Name);
    }
}
```

出力イメージ：

```text
中村
```

### virtual

親クラス側で「あとで子クラスで書き換えてよい」と示すときに `virtual` を使います。

```csharp
using System;

    {
        Console.WriteLine("何か鳴きます");
    }
}

{
    static void Main(string[] args)

    }

```

出力イメージ：

```text
何か鳴きます
```

### override

子クラス側で親クラスの動きを書き換えるときに `override` を使います。

```csharp
using System;

class Animal
{
    public virtual void Speak()
    {
        Console.WriteLine("何か鳴きます");
    }
}

class Dog : Animal
{
    public override void Speak()
    {
        Console.WriteLine("ワンワン");
    }
}

class Program
{
    static void Main(string[] args)
    {
        Dog dog = new Dog();
        dog.Speak();
    }
}
```

出力イメージ：

```text
ワンワン
```

### 親型の変数に子を入れる

親クラスの型の変数に、子クラスの実物を入れられることがあります。  
これで「共通の入口で扱う」書き方ができます。

```csharp
using System;

class Animal
{
    public virtual void Speak()
    {
        Console.WriteLine("何か鳴きます");
    }
}

class Cat : Animal
{
    public override void Speak()
    {
        Console.WriteLine("ニャー");
    }
}

class Program
{
    static void Main(string[] args)
    {
        Animal animal = new Cat();
        animal.Speak();
    }
}
```

出力イメージ：

```text
ニャー
```

### protected

`protected` は、親クラスと、それを引き継いだ子クラスの中で使えるようにしたいときに使います。  
ここでは「外からは見せず、引き継いだ側には見せる」と考えれば十分です。

```csharp
using System;

class Animal
{
    protected string Name;

    public void SetName(string name)
    {
        Name = name;
    }
}

class Dog : Animal
{
    public void ShowName()
    {
        Console.WriteLine(Name);
    }
}

class Program
{
    static void Main(string[] args)
    {
        Dog dog = new Dog();
        dog.SetName("ポチ");
        dog.ShowName();
    }
}
```

出力イメージ：

```text
ポチ
```

## 例外

### 例外とは

例外は、「そのままでは処理を続けられない失敗が起きた」と知らせる仕組みです。  
ここでは「エラーを知らせる特別な流れ」だと思えば大丈夫です。

```csharp
using System;

class Program
{
    static void Main(string[] args)
    {
        Console.WriteLine("例外は失敗を知らせる仕組みです");
    }
}
```

出力イメージ：

```text
例外は失敗を知らせる仕組みです
```

### try と catch

失敗するかもしれない場所を `try` に書き、失敗したときの処理を `catch` に書きます。

```csharp
using System;

class Program
{
    static void Main(string[] args)
    {
        try
        {
            int number = int.Parse("abc");
            Console.WriteLine(number);
        }
        catch (Exception)
        {
            Console.WriteLine("数字に変換できませんでした");
        }
    }
}
```

出力イメージ：

```text
数字に変換できませんでした
```

### finally

成功しても失敗しても最後に必ずやりたい処理は `finally` に書きます。

```csharp
using System;

class Program
{
    static void Main(string[] args)
    {
        try
        {
            Console.WriteLine("処理を始めます");
        }
        finally
        {
            Console.WriteLine("最後に必ずここを通ります");
        }
    }
}
```

出力イメージ：

```text
処理を始めます
最後に必ずここを通ります
```

### 例外オブジェクト

`catch` の丸かっこの中で受け取るものには、失敗の内容が入っています。

```csharp
using System;

class Program
{
    static void Main(string[] args)
    {
        try
        {
            int number = int.Parse("abc");
            Console.WriteLine(number);
        }
        catch (Exception ex)
        {
            Console.WriteLine(ex.Message);
        }
    }
}
```

出力イメージ：

```text
入力文字列の形式が正しくありません。
```

### 特定の例外だけ捕まえる

失敗の種類ごとに分けたいときは、例外の種類を書きます。

```csharp
using System;

class Program
{
    static void Main(string[] args)
    {
        try
        {
            int number = int.Parse("abc");
            Console.WriteLine(number);
        }
        catch (FormatException)
        {
            Console.WriteLine("数字の形ではありませんでした");
        }
    }
}
```

出力イメージ：

```text
数字の形ではありませんでした
```

### 自分で例外を投げる

自分で「この値では処理できません」と知らせたいときは `throw` を使います。

```csharp
using System;

class Program
{
    static int Divide(int a, int b)
    {
        if (b == 0)
        {
            throw new ArgumentException("0 では割れません");
        }

        return a / b;
    }

    static void Main(string[] args)
    {
        try
        {
            Console.WriteLine(Divide(10, 0));
        }
        catch (ArgumentException ex)
        {
            Console.WriteLine(ex.Message);
        }
    }
}
```

出力イメージ：

```text
0 では割れません
```

### 例外を投げない書き方との使い分け

毎回失敗の可能性が高い入力では、`TryParse` のような「例外を使わずに結果を返す書き方」のほうが読みやすいことがあります。

```csharp
using System;

class Program
{
    static void Main(string[] args)
    {
        int number;

        if (int.TryParse("123", out number))
        {
            Console.WriteLine(number);
        }
        else
        {
            Console.WriteLine("数字ではありません");
        }
    }
}
```

出力イメージ：

```text
123
```

### 複数の catch

失敗の種類ごとに、別の対応を書けます。

```csharp
using System;
using System.IO;

class Program
{
    static void Main(string[] args)
    {
        try
        {
            string text = File.ReadAllText("missing.txt");
            int number = int.Parse(text);
            Console.WriteLine(number);
        }
        catch (FileNotFoundException)
        {
            Console.WriteLine("ファイルが見つかりません");
        }
        catch (FormatException)
        {
            Console.WriteLine("数字の形ではありません");
        }
    }
}
```

出力イメージ：

```text
ファイルが見つかりません
```

### 入力と例外

入力では、失敗しそうな場所を想像しておくことが大事です。

```csharp
using System;

class Program
{
    static void Main(string[] args)
    {
        Console.Write("数字を入力してください: ");
        string text = Console.ReadLine();

        try
        {
            int number = int.Parse(text);
            Console.WriteLine(number * 2);
        }
        catch (FormatException)
        {
            Console.WriteLine("数字を入れてください");
        }
    }
}
```

出力イメージ：

```text
数字を入力してください: abc
数字を入れてください
```

### 例外をそのままにしない

失敗したのに何も出さないと、原因がわかりにくくなります。  
最初は「失敗したら何かしらの説明を出す」を意識すると十分です。

```csharp
using System;

class Program
{
    static void Main(string[] args)
    {
        try
        {
            throw new Exception();
        }
        catch (Exception)
        {
            Console.WriteLine("失敗しました");
        }
    }
}
```

出力イメージ：

```text
失敗しました
```

### using 文との関係

ファイルのように「使い終わったら閉じたいもの」は、`using` 文と相性がよいです。  
例外が起きても片付けやすくなります。

```csharp
using System;
using System.IO;

class Program
{
    static void Main(string[] args)
    {
        using (StringWriter writer = new StringWriter())
        {
            writer.WriteLine("abc");
            Console.Write(writer.ToString());
        }
    }
}
```

出力イメージ：

```text
abc
```

## 第十二章まとめ

- 例外は、失敗を知らせる仕組み
- `try` に試す処理、`catch` に失敗時の処理を書く
- `finally` は最後に必ず通る
- `throw` で自分で失敗を知らせられる
- 毎回起こりうる入力失敗では `TryParse` のような書き方も大事

## コレクション

### コレクションとは

コレクションは、「複数の値をまとめて扱う入れ物」です。  
配列と似ていますが、あとから増やしたり減らしたりしやすいものが多いです。

```csharp
using System;
using System.Collections.Generic;

class Program
{
    static void Main(string[] args)
    {
        Console.WriteLine("コレクションは複数の値をまとめて扱います");
    }
}
```

出力イメージ：

```text
コレクションは複数の値をまとめて扱います
```

### using System.Collections.Generic

`List<T>` や `Dictionary<TKey, TValue>` を使うには、この道具箱を読み込みます。

```csharp
using System;
using System.Collections.Generic;

class Program
{
    static void Main(string[] args)
    {
        Console.WriteLine("List と Dictionary を使えるようにします");
    }
}
```

出力イメージ：

```text
List と Dictionary を使えるようにします
```

### List<T>

`List<T>` は、要素をあとから追加しやすい並びの入れ物です。  
`<T>` の部分には、何を入れるかを書きます。

```csharp
using System;
using System.Collections.Generic;

class Program
{
    static void Main(string[] args)
    {
        List<int> numbers = new List<int>();
        numbers.Add(10);
        numbers.Add(20);
        numbers.Add(30);

        Console.WriteLine(numbers.Count);
    }
}
```

出力イメージ：

```text
3
```

### foreach

全部の要素を順に見るとき、`foreach` もよく使います。  
ここでは「1つずつ取り出して順番に見る書き方」と考えれば十分です。

```csharp
using System;
```

```text
青
緑
```

### Contains

```csharp
using System;
```

### Dictionary<TKey, TValue>

`Dictionary<TKey, TValue>` は、「名前で値を探す」入れ物です。  
ここでは「見出しと中身の組み合わせを持つ箱」と考えれば大丈夫です。

```csharp
using System;

        Console.WriteLine(scores["英語"]);
```

```text
80
90
```

### キーと値

`Dictionary` では、探すための名前をキー、その中身を値と呼びます。  
ここでは「見出し」と「中身」くらいの理解で十分です。

```csharp
using System;
using System.Collections.Generic;

class Program
{
    static void Main(string[] args)

        Console.WriteLine(capitals["日本"]);
    }

```

出力イメージ：

```text
東京
```

### TryGetValue

見つからないときの失敗を減らしたいなら `TryGetValue` が便利です。

```csharp
using System;
using System.Collections.Generic;

class Program
{
    static void Main(string[] args)
    {
        Dictionary<string, int> scores = new Dictionary<string, int>();
        scores["国語"] = 75;

        int value;

        if (scores.TryGetValue("国語", out value))
        {
            Console.WriteLine(value);
        }
        else
        {
            Console.WriteLine("見つかりません");
        }
    }
}
```

出力イメージ：

```text
75
```

### クラスを List に入れる

### Queue<T>

先に入れたものから先に出す入れ物を `Queue<T>` といいます。  
ここでは「並んだ順に取り出す箱」と考えれば十分です。

```csharp
using System;
using System.Collections.Generic;

class Program
{
    static void Main(string[] args)
    {
        Queue<string> queue = new Queue<string>();
        queue.Enqueue("A");
        queue.Enqueue("B");

        Console.WriteLine(queue.Dequeue());
        Console.WriteLine(queue.Dequeue());
    }
}
```

出力イメージ：

```text
A
B
```

### Stack<T>

あとから入れたものを先に出す入れ物を `Stack<T>` といいます。  
ここでは「上に積んで、あとから積んだものから取る箱」と考えれば十分です。

```csharp
using System;
using System.Collections.Generic;

class Program
{
    static void Main(string[] args)
    {
        Stack<string> stack = new Stack<string>();
        stack.Push("A");
        stack.Push("B");

        Console.WriteLine(stack.Pop());
        Console.WriteLine(stack.Pop());
    }
}
```

出力イメージ：

```text
B
A
```

### 配列と List の違い

配列は最初に個数を決めるのが基本です。  
`List<T>` はあとから増やしやすいです。

```csharp
using System;
using System.Collections.Generic;

class Program
{
    static void Main(string[] args)
    {
        int[] array = new int[2];
        List<int> list = new List<int>();

        list.Add(10);
        list.Add(20);
        list.Add(30);

        Console.WriteLine(array.Length);
        Console.WriteLine(list.Count);
    }
}
```

出力イメージ：

```text
2
3
```

## 第十三章まとめ

- コレクションは、複数の値をまとめて扱う入れ物
- `List<T>` は増減しやすい並びの入れ物
- `Dictionary<TKey, TValue>` は名前で探せる入れ物
- `foreach` で順に見られる
- `Queue<T>` と `Stack<T>` は取り出す順番が違う
