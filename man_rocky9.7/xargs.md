# xargs(1) — 標準入力から引数を作ってコマンド実行

`xargs` は、標準入力から“項目（items）”を読み取り、**それらを引数にしてコマンドをまとめて実行**します。

- `find` で見つけたファイルに一括で `chmod`/`grep`/`rm` を当てたい
- `cut/awk` で抜いたID一覧に対してAPI呼び出しをしたい
- 1件ずつ実行だと遅いので、ある程度まとめて実行したい

…みたいな運用で使います。

ただし `xargs` は **空白/改行を含むファイル名**で事故りやすいので、まずこの結論だけ覚えるのが安全です。

## まず結論（最重要）

- ファイル名を扱うなら、基本は **`find -print0 | xargs -0`**（NUL区切り）
- 置換実行（テンプレ展開）したいなら **`xargs -I{}`**（ただし遅め・制約あり）
- 並列化したいなら **`-P`**（ただし対象コマンド側の並列安全性は自分で担保）

## まず結論：よく使うコマンド

```bash
# 1) find の結果を安全に渡す（空白/改行入りファイル名でも安全）
find . -type f -name '*.log' -print0 | xargs -0 grep -nH 'ERROR'

# 2) “1個ずつ”実行したい（1引数=1実行）
find . -type f -name '*.log' -print0 | xargs -0 -n 1 wc -l

# 3) 置換（テンプレ）でコマンドを作りたい
# {} を入力項目で置換して実行（入力の区切りは基本的に改行になる）
printf '%s\n' a b c | xargs -I{} echo 'item={}'

# 4) 対話確認しながら（実行前プロンプト）
find . -type f -name '*.tmp' -print0 | xargs -0 -p rm -v

# 5) 実行内容を表示（デバッグ）
find . -type f -name '*.tmp' -print0 | xargs -0 -t rm -v

# 6) 空入力のとき実行しない（GNU拡張：-r / --no-run-if-empty）
# ※ rm を誤って "rm" 単体で実行する系の事故回避
cat maybe_empty_list.txt | xargs -r rm

# 7) 並列実行（例：4並列）
# -n と組み合わせないと、1回しか exec されないことがある
printf '%s\n' *.log | xargs -n 1 -P 4 gzip -9

# 8) 引数上限（ARG_MAX 等）を確認
xargs --show-limits
```

## SYNOPSIS（書式）

```text
xargs [options] [command [initial-arguments]]
```

- `command` を省略するとデフォルトは `echo`（実行確認に便利だが、事故の元にもなる）
- 標準入力から項目を読み、項目を引数として `command` を複数回起動する

## xargs が“速い”理由

入力項目が 1万個あるときに、

- 1件ずつコマンド実行（1万回起動）
- xargs でまとめて実行（数十回〜数百回の起動）

となり、**プロセス起動回数が激減**して速くなります。

ただし、OS には「1回の exec に渡せる引数の総サイズ上限」があり、`xargs` はその上限に達するまで引数を詰めます。

## 区切り（delimiter）と “-0（NUL区切り）”

### デフォルトは危険（空白/改行で壊れる）

`xargs` のデフォルトは「空白（blanks）または改行」で区切ります。
なので、ファイル名に空白があると **別々の項目に割れて事故**ります。

### `-0`（`--null`）が安全

`-0` を付けると、区切りが NUL（`\0`）になります。

- `find -print0` が NUL 区切りを出す
- `xargs -0` が NUL 区切りを読む

この組み合わせが“安全な定番”です。

```bash
find /var/log -type f -name '*.log' -print0 | xargs -0 grep -nH 'ERROR'
```

補足：`man xargs` にある通り、`-0` のときは **クォートやバックスラッシュが特別扱いされず**、入力の各文字はそのまま扱われます。

### `-d delim`（`--delimiter=delim`）

「改行区切り」だけで十分なら `-d '\n'` のように明示もできますが、
ファイル名が絡むなら基本は `-0` が無難です。

## “何個ずつ”渡すか（-n / -L）

### `-n max-args`

1回の実行に渡す「引数の個数」を制限します。

```bash
# 1回の gzip に1ファイルずつ渡す
printf '%s\n' *.log | xargs -n 1 gzip -9
```

### `-L max-lines`

「入力の非空行を何行ずつ使うか」です。
（`-I` を使うと暗黙に `-L 1` 相当になりがちです。`man xargs` では `-I` が `-L 1` を暗黙に含むと説明されています）

## 置換テンプレ（-I）

`-I replace-str` は、初期引数の中の `replace-str` を、入力項目に置換して実行します。

```bash
printf '%s\n' a b c | xargs -I{} echo 'name={}'
```

注意（運用の落とし穴）：

- `-I` を使うと、入力項目の区切りが“実質的に改行”になる（空白で割れない）
- `-I` は 1項目ずつ（1行ずつ）実行になりやすく、**まとめ実行の旨味が減る**
- `man xargs` の BUGS にある通り、`-I` には **入力行長の上限**が絡みやすい

`-I` は便利ですが、まず `-0`+`-n` で済まないか検討するのが無難です。

## 並列実行（-P）

`-P max-procs` で同時実行数を増やせます。

```bash
# 4並列で1件ずつ
printf '%s\n' *.log | xargs -n 1 -P 4 gzip -9
```

注意：

- 対象コマンドが並列実行に耐えるか（同じファイルを書き換えない等）は自分で担保する
- `-P` 単体だと 1回しか exec されないケースがあり得るので、だいたい `-n` や `-L` とセットにする

## 空入力で実行しない（-r）

GNU xargs では `-r`（`--no-run-if-empty`）が便利です。

```bash
# 空なら rm を実行しない
cat list.txt | xargs -r rm
```

「空のときに `rm` が引数無しで呼ばれてエラー」程度ならまだ良いですが、
自作コマンドなどで“引数無し時の挙動が危険”な場合もあるので、保険として有効です。

## 実行内容を確認（-t / -p）

- `-t`：実行するコマンド行を stderr に出す（ログ/デバッグ向け）
- `-p`：実行前に確認プロンプト（対話）

```bash
find . -type f -name '*.tmp' -print0 | xargs -0 -t rm -v
find . -type f -name '*.tmp' -print0 | xargs -0 -p rm -v
```

## セキュリティ注意：TOCTOU（時間差）

`man xargs` の BUGS にある通り、`xargs` は本質的に「一覧を作る」と「実際に使う」に時間差ができ、
他者がファイルを差し替える等の攻撃（TOCTOU）に弱い場面があります。

- 共有環境/権限が絡む場所での破壊的操作（`rm`/`chmod` 等）は慎重に
- より安全な代替として `find -execdir ...` が推奨されるケースがある

（普段の自分だけの運用でも、“意図しないファイルまで触る”事故の温床になりやすい点は同じです）

## 引数上限の確認（--show-limits）

OS の上限（ARG_MAX など）に依存するので、環境で限界を知りたいなら：

```bash
xargs --show-limits
```

## 終了コード（exit status）

`info xargs`（findutils の `Invoking xargs`）に明記があります。

- `0`：成功
- `123`：呼び出したコマンドのいずれかが `1..125` で終了
- `124`：呼び出したコマンドが `255` で終了（この場合 xargs は即停止する挙動がある）
- `125`：呼び出したコマンドがシグナルで終了
- `126`：コマンドが実行できない
- `127`：コマンドが見つからない
- `1`：その他のエラー

注意：シェルでは `128+N` が「シグナルで死んだ」を表すのに使われることがあります。

## 事故りポイント（xargs あるある）

- **空白/改行入りファイル名で壊れる** → `find -print0 | xargs -0` を基本に
- `-I{}` を便利に使いすぎて遅い/制約に当たる → まず `-0`+`-n` を検討
- 並列 `-P` で競合（同じファイルを複数プロセスが触る等） → 対象コマンドの排他を設計
- 実行内容が想定と違う → `-t` で表示、危険操作は `-p` で確認
