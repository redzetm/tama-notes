# nmap(1) — ネットワーク調査（許可された範囲で）

`nmap` は、対象ホストの疎通確認や開放ポートの確認、サービス推定（バナー/プローブ）などに使う調査コマンドです。

重要：`nmap` は強力で、環境によってはスキャンがアラート扱いになります。
**必ず許可された範囲（自分の管理下/合意済みのネットワーク）でのみ**使い、業務では「目的・対象・時間帯・負荷」を明確にして実行します。

## まず結論：よく使うコマンド

```bash
# 1) まず疎通（ping相当）: 生きているホストだけ列挙
nmap -sn 192.168.1.0/24

# 2) まず最小のポート確認: 代表的なTCPポート（高速）
# -sS は権限が必要なことがあります（環境により sudo 推奨）
sudo nmap -sS --top-ports 50 192.168.1.10

# 3) 特定ポートだけ確認（運用の定番）
# 例: SSH/HTTP/HTTPS
nmap -p 22,80,443 192.168.1.10

# 4) サービス推定（何が動いてるか）
# -sV は通信が増えるので、対象と時間帯を選ぶ
sudo nmap -sS -sV -p 22,80,443 192.168.1.10

# 5) 結果をファイルへ保存（後で報告しやすい）
# -oA は .nmap/.gnmap/.xml をまとめて出す
nmap -p 22,80,443 -oA nmap_192.168.1.10 192.168.1.10

# 6) どの理由でそう判断したか（調査向け）
nmap --reason -p 22,80,443 192.168.1.10

# 7) 開いているものだけ表示（大量スキャン時に便利）
nmap --open -p 1-1024 192.168.1.10
```

## SYNOPSIS（書式）

```text
nmap [Scan Type(s)] [Options] {target specification}
```

ターゲット指定の例：

```text
192.168.1.10
192.168.1.0/24
example.internal
-iL targets.txt
```

## まず押さえる：状態（open/closed/filtered）

- **open**: そのポートで何かが待ち受けている可能性が高い
- **closed**: 到達できるが待ち受けが無い（RST 等）
- **filtered**: 到達可否が判断できない（FW/ACL で落とされている等）

運用では「open なのに繋がらない」「filtered で通らない」を分けて考えると速いです。

## 典型タスク

### 疎通（生存）確認：`-sn`

```bash
# ホスト発見のみ（ポートスキャンしない）
nmap -sn 192.168.1.0/24
```

- 「サブネット内で生きているIPをざっくり列挙」用途
- ICMP や ARP 等、環境により手段が変わります

### TCP ポートスキャン：`-sS` / `-sT`

```bash
# TCP SYN スキャン（代表的。権限が必要なことあり）
sudo nmap -sS -p 1-1024 192.168.1.10

# TCP connect スキャン（権限不要になりやすいが遅め）
nmap -sT -p 1-1024 192.168.1.10
```

使い分けの目安：

- `-sS`: 調査でよく使う。速度/精度のバランスが良いことが多い
- `-sT`: 権限が無い環境や制約下での代替

### UDP スキャン：`-sU`（難しい・時間がかかる）

UDP は判定が難しく時間がかかりやすいので、最初はポートを絞るのが基本です。

```bash
# 例: DNS/NTP/SNMP など、疑っているポートだけ
sudo nmap -sU -p 53,123,161 192.168.1.10
```

### ポート指定：`-p` / `--top-ports`

```bash
# 単発ポート
nmap -p 22 192.168.1.10

# 複数
nmap -p 22,80,443 192.168.1.10

# 範囲
nmap -p 1-1024 192.168.1.10

# よくある上位ポートから
sudo nmap -sS --top-ports 100 192.168.1.10
```

### サービス推定：`-sV`

「開いてる」だけでなく「何が動いてるか」を当てに行きます。
調査の価値は高い一方、通信量も増えるので対象を絞るのが安全です。

```bash
sudo nmap -sS -sV -p 22,80,443 192.168.1.10
```

### OS 推定：`-O`（環境によって精度/権限に依存）

```bash
sudo nmap -O 192.168.1.10
```

運用では「OS断定」よりも、
パッケージ/サービスの実体はサーバ側で `rpm -q` や `systemctl status` で確定させるのが安全です。

### スキャン対象の指定：`-iL` / `--exclude`

```bash
# 対象をファイルで渡す（1行1ターゲット）
nmap -iL targets.txt -p 22,80,443

# 除外
nmap 192.168.1.0/24 --exclude 192.168.1.1,192.168.1.254
```

### 出力：`-oN/-oG/-oX/-oA`

```bash
# 人間向け
nmap -p 22,80,443 -oN scan.nmap 192.168.1.10

# grep しやすい形式（用途限定）
nmap -p 22,80,443 -oG scan.gnmap 192.168.1.10

# XML（後処理向け）
nmap -p 22,80,443 -oX scan.xml 192.168.1.10

# まとめて
nmap -p 22,80,443 -oA scan 192.168.1.10
```

## 運用の切り分けに使うコツ

### 1) サーバ側の待受と突合する

`nmap` は外形の観測です。サーバ側の事実と突合すると切り分けが速いです。

- サーバ側：`ss -lntup`（待受）
- FW：`firewall-cmd --list-all`（ゾーン/サービス/ポート/rich rule）
- ログ：`journalctl -u <UNIT> -b -e`

### 2) `filtered` は「FW/経路/ACL」を疑う

- `open` なのに繋がらない → アプリ側（認証/上位プロトコル/到達経路）も疑う
- `filtered` → FW や経路の途中で落ちている可能性が高い

## 事故りやすい点（短く）

- 許可なくスキャンしない（監視やIDSでインシデント扱いになり得る）
- まずポートを絞る（`-p` / `--top-ports`）
- `-sV`/`-O` は通信が増えがちなので対象/時間帯を選ぶ
- 結果は `-oA` 等で保存して、後で報告・差分比較できるようにする
