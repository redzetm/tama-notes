title: "top(1) プロセス監視・負荷調査コマンド実用ノート（Rocky Linux 9.7）"
top


top -d 1

`top` は Linux の稼働状況を **リアルタイム**に観測するツールです。
top -H

運用では「遅い/重い/メモリ食い/IO待ちが長い」などの原因を *まず見に行く* 入口として使います。
このノートは `man top` を土台に、**コピペできる観測手順と、押すキーだけ覚えれば使える**形に整理します。

## まず結論：困ったらこれ

```bash
# まず普通に起動
top

# 更新間隔 1 秒（通常はこれで十分）
top -d 1

# スレッド単位で見る（Java / DB / 代理プロセスの調査で有用）
top -H

# 特定 PID だけ追う（対象が分かっている時の最短）
top -p 1234

# バッチ出力（ログに残す/比較する。例：5回だけ、1秒間隔）
top -b -d 1 -n 5

# バッチでソートキーを固定（例：%CPU で降順）
top -b -n 1 -o +%CPU
```

## 画面の構造（どこを見ればいいか）

`top` の表示は大きく3つです。

1. **Summary Area（サマリ）**
   - uptime / load average
   - タスク数（running/sleeping/stopped/zombie）
   - CPU states（`us sy ni id wa hi si st` など）
   - メモリ/スワップ（total/free/used/buff/cache、avail など）
2. **Columns Header（列名）**
   - `PID USER PR NI VIRT RES SHR S %CPU %MEM TIME+ COMMAND` など
3. **Task Area（一覧）**
   - プロセス（または `-H` でスレッド）

最初の観測で重要なのはだいたい次の3点です。

- load average が高い（CPU詰まり/IO詰まり/待ち行列が長い）
- CPU states の `wa`（I/O wait）が高い（ディスク/ストレージ/ネットワークIOの疑い）
- メモリの `avail` が少ない + swap を使っている（メモリ逼迫の疑い）

## よく使うキー（覚えるのはこれだけ）

`top` は対話操作が本体です。

- `h` または `?`：ヘルプ
- `q`：終了
- `P`：%CPU でソート
- `M`：%MEM でソート
- `T`：TIME（CPU時間）でソート
- `1`：CPUを1行表示/CPU別表示を切り替え
- `H`：スレッド表示 ON/OFF（`-H` と同じ）
- `c`：COMMAND を「コマンドライン」表示/「プログラム名」表示 切り替え
- `i`：アイドル（前回更新以降CPU未使用）のタスクを隠す/表示
- `k`：kill（PID と signal を入力して送る）
- `r`：renice（PID と nice 値を入力）
- `f` または `F`：表示列の追加/削除・順番変更（Fields Management）
- `o` または `O`：フィルタ（Other Filtering）
- `W`：現在の設定を rcfile に保存

## 起動オプション（運用で使う範囲）

`top` のコマンドラインは多機能ですが、運用では次が中心です。

- `-d ss.t`
  - 更新間隔（秒）。例：`-d 1`、`-d 0.5`
  - 0 はほぼ連続更新になり見づらい/負荷にもなるので注意
- `-H`
  - スレッド単位で表示（原因がスレッドにある時に有効）
- `-p PIDLIST`
  - 指定 PID だけ監視（最大20個まで）
  - `-p 1111 -p 2222` でも `-p 1111,2222` でもOK
  - 0 を指定すると top 自身を指す
- `-u user` / `-U user`
  - ユーザーで絞る
  - `-u` は effective user、`-U` は real/effective/saved/fs のいずれか
  - `!user` で否定も可能
- `-o fieldname`
  - ソート列を指定（特にバッチで重要）
  - `+field` で高→低、`-field` で低→高
- `-O`
  - `-o` に指定できる field 名一覧を出して終了
- `-b`
  - バッチモード（非対話で出力）。ログ保存/比較/定期観測に使う
- `-n number`
  - バッチ時の繰り返し回数（フレーム数）
- `-w [cols]`
  - 出力幅（バッチで横幅を固定したい時）

## 実用レシピ（コピペで使う）

### 1) 重い時の最短手順

1. `top` を起動
2. `P` を押して %CPU ソート（CPU食いを見る）
3. `M` を押して %MEM ソート（メモリ食いを見る）
4. `1` で CPU別表示にして偏りを見る（特定CPUに張り付いていないか）
5. `H` でスレッド表示にして、プロセス内のホットスレッドを見る

### 2) 目的の PID を追う（すでに PID が分かっている）

```bash
top -p 1234
```

- `c` でコマンドライン表示にして、実体（引数）を把握する
- `H` でスレッドに落として原因スレッドを探す

### 3) バッチで証跡を残す（後で比較する）

```bash
# 例：1秒間隔で30秒分
top -b -d 1 -n 30 > top_30s.txt

# 例：%MEM ソートを固定して1回だけ（スナップショット）
top -b -n 1 -o +%MEM
```

バッチは「その瞬間の画面を保存」できるのが価値です。
インシデント対応で「あとで状況を説明する」時に役立ちます。

### 4) load average が高い時の読み方（ざっくり）

- load average は「CPU に限らず *実行待ち* が溜まっている」指標です
- `wa` が高い → IO待ちが疑わしい
- `id` が低く `us/sy` が高い → CPU を実際に使い切っている可能性
- `st` が高い（VM）→ ハイパーバイザに CPU を盗られている可能性

※ ここでの切り分けは入口で、最終的には `iostat`/`vmstat`/`pidstat` などに繋げます。

## フィールド（列）の意味：最低限

環境や設定で表示列は変わります。まずは以下だけ覚えると実用になります。

- `PID`：プロセスID
- `USER`：所有ユーザー（effective user）
- `PR`：優先度（`rt` は realtime）
- `NI`：nice 値（負なら優先度高め、正なら低め）
- `S`：状態（R/S/D/Z など）
- `%CPU`：CPU使用率
- `%MEM`：物理メモリに対する RES 比率（ざっくり）
- `RES`：実メモリ使用量（resident）
- `VIRT`：仮想メモリ使用量（予約も含むので過大に見えることがある）
- `TIME` / `TIME+`：CPU使用時間
- `COMMAND`：コマンド名/コマンドライン（`c` で切替）

## 設定ファイル（保存先の目安）

`W` キーで現在の設定（表示列、ソート、トグル等）を保存できます。
man 記載では、rcfile はおおむね次のどちらかに置かれます（環境により差があります）。

- 旧形式：`$HOME/.<name>-4-toprc`（先頭ドット）
- 新形式：`$XDG_CONFIG_HOME/procps/<name>-4-toprc` または `$HOME/.config/procps/<name>-4-toprc`

## 事故りやすい点（短く）

- `k` / `r` が効かない（またはヘルプに出ない）
  - Secure mode の可能性があります（システム制限ファイルで抑止される）
- 表示が崩れる
  - まず何かキーを押して再描画、ダメなら `^Z` → `fg`、それでもダメなら `reset`
- 横幅が足りない
  - バッチなら `-w`、対話なら列を減らす（`f`）か端末幅を広げる

## 参考：終了の基本

- `q` で終了（または `Ctrl-C`）
