# test(1) — 条件式を評価して終了ステータスを返す

`test` は、**条件式（EXPRESSION）を評価して終了ステータスで true/false を返す**コマンド（多くのシェルではビルトイン）です。
シェルスクリプトの `if` / `while` / `&&` / `||` の基礎として頻出します。

- true（条件成立）: 終了ステータス `0`
- false（条件不成立）: 終了ステータス `1`
- 文法エラーなど: 終了ステータス `2`（実装依存だが、だいたいこの扱い）

同じ用途でよく使われる表記として、`[` ... `]` 形式があります（後述）。

## SYNOPSIS（書式）

```sh
test EXPRESSION

[ EXPRESSION ]
```

ポイント：`[` は **コマンド名**です。最後の `]` は **引数**として必要です。

```sh
# OK
[ -f /etc/passwd ]

# NG（末尾の ] がない）
[ -f /etc/passwd
```

## まず結論：運用・スクリプトでよく使う形

```sh
# ファイルが存在するか
[ -e "$path" ]

# 通常ファイルか（ディレクトリ除外）
[ -f "$path" ]

# ディレクトリか
[ -d "$path" ]

# 文字列が空でない / 空
[ -n "$s" ]
[ -z "$s" ]

# 数値比較（= は使わない）
[ "$n" -ge 10 ]

# AND/OR は -a/-o より &&/||（曖昧さ回避）
[ -n "$a" ] && [ -n "$b" ]
[ -e "$f" ] || echo "missing" >&2
```

## EXPRESSION（条件式）の考え方

`test` の EXPRESSION はだいたい次の部品で組み立てます。

- **単項**（1つの値を見る）: `-e FILE`, `-n STRING`, `-z STRING`, ...
- **二項**（2つを比較する）: `STRING1 = STRING2`, `INTEGER1 -ge INTEGER2`, ...
- **否定**: `! EXPR`
- **括弧**: `( EXPR )`（※シェルの都合でエスケープが必要なことがある）

### 文字列テスト

```sh
# 非空
[ -n "$s" ]

# 空
[ -z "$s" ]

# 同一
[ "$a" = "$b" ]

# 非同一
[ "$a" != "$b" ]
```

重要：**必ずクォートする**のが基本です（後述）。

### 数値テスト

```sh
[ "$x" -eq "$y" ]  # 等しい
[ "$x" -ne "$y" ]  # 等しくない
[ "$x" -lt "$y" ]  # より小さい
[ "$x" -le "$y" ]  # 以下
[ "$x" -gt "$y" ]  # より大きい
[ "$x" -ge "$y" ]  # 以上
```

注意：`[ "$x" = 10 ]` は **文字列比較**です。数値比較は `-eq/-ge/...` を使います。

### ファイルテスト（代表）

```sh
[ -e FILE ]  # 存在する
[ -f FILE ]  # 通常ファイル
[ -d FILE ]  # ディレクトリ
[ -L FILE ]  # シンボリックリンク
[ -r FILE ]  # 読み取り可
[ -w FILE ]  # 書き込み可
[ -x FILE ]  # 実行（またはディレクトリ検索）可
[ -s FILE ]  # サイズが 0 より大
```

時間や同一性比較（切り分けで地味に便利）：

```sh
[ "$a" -nt "$b" ]  # a が b より新しい（mtime）
[ "$a" -ot "$b" ]  # a が b より古い
[ "$a" -ef "$b" ]  # device/inode が同じ（同一ファイルか）
```

TTY 判定：

```sh
# fd 1（stdout）が端末か？
[ -t 1 ] && echo "interactive" || echo "not a tty"
```

## 事故りポイント（重要）

### 1) 変数は基本クォートする（空/スペース/先頭ハイフン）

クォートしないと、次の事故が起きます。

- 変数が空 → 引数が欠けて文法エラー
- スペースを含む → 引数が分割される
- `-n` のような値 → オプション扱いっぽく見えて式が壊れる

```sh
# NG（空だと「[ = x ]」みたいになって壊れる）
[ $a = x ]

# OK
[ "$a" = x ]
```

### 2) `-a` / `-o` は曖昧なので避ける（&& / || を使う）

`test` の `EXPR1 -a EXPR2`（AND）と `EXPR1 -o EXPR2`（OR）は、
**演算子の優先順位・パースが実装差で事故りやすい**ため、実用では避けるのが無難です。

```sh
# 推奨（明示的で読みやすい）
[ -n "$a" ] && [ -n "$b" ]
[ -e "$f" ] || exit 1
```

### 3) `(` `)` はシェルが解釈するので注意

`test` 自体は `( EXPR )` をサポートしますが、
`(` `)` はシェルでも特別扱いされるため、
特に古い `sh` 互換スクリプトでは **エスケープが必要**になりがちです。

```sh
# 例：sh ではこう書く方が安全なことが多い
[ \( -n "$a" \) ]
```

（ただしこの書き方自体が読みづらいので、可能なら `if ...; then ...; fi` と `&&/||` で表現するのが安全です）

### 4) `-L` と「シンボリックリンクの追跡」

`-L`（または `-h`）は「そのパス自体が symlink か」を見ます。
一方で、多くのファイルテスト（`-e/-f/-d` など）は **symlink を辿って判定**します。

- symlink そのものを検出したい → `-L`
- symlink の指す先が存在/通常ファイルか見たい → `-e/-f`

```sh
[ -L "$p" ] && echo "this is a symlink"
[ -e "$p" ] && echo "target exists (or p exists if not symlink)"
```

## `test` / `[` / `[[` の違い（混同しやすい）

### `test` と `[` はほぼ同義（`[` は末尾 `]` が必要）

- `test EXPR` と `[ EXPR ]` は、だいたい同じ意味です
- `[` はコマンド名なので `]` が必要

### `[[ ... ]]` は「コマンド」ではなく、主に bash の構文（キーワード）

`[[ ... ]]` は bash 等の拡張で、
`test`/`[` より **事故りにくい**（ワード分割・グロブの扱いなど）一方、
**POSIX sh 互換ではありません**。

運用の目安：

- POSIX `sh` 互換スクリプトにしたい → `test` / `[ ... ]`
- bash 前提で安全性・書きやすさを優先 → `[[ ... ]]`

確認コマンド：

```sh
type test
type [

# bash なら、ビルトインの説明
help test
help [
```

## 具体例：ありがちな用途

### 1) 引数チェック（空なら使い方を出す）

```sh
#!/bin/sh

if [ $# -lt 1 ]; then
  echo "usage: $0 FILE" >&2
  exit 2
fi

f=$1
if [ ! -e "$f" ]; then
  echo "not found: $f" >&2
  exit 1
fi
```

### 2) ファイルがあれば処理、なければスキップ

```sh
if [ -f "$f" ]; then
  echo "processing..."
  # ...
else
  echo "skip (not a regular file): $f" >&2
fi
```

### 3) 置換・展開時の空文字対策

```sh
# 例：環境変数が未設定ならデフォルト
if [ -z "${PORT}" ]; then
  PORT=8080
fi
```
