# sort(1) — 行を並べ替える（ソート/チェック/マージ）

`sort` は「行を並べ替える」ためのコマンドです。
運用では、ログや集計結果を **並べる→上位を取る→重複を潰す** みたいな用途で頻出です。

`sort` は見た目以上に奥が深く、事故の大半は次の2つです。

- **locale（`LC_COLLATE`）の影響**で順序が期待とズレる
- **キー指定（`-k`）と区切り（`-t`）**の解釈ミス

## まず結論：よく使うコマンド

```bash
# 1) 単純ソート（辞書順）
sort file

# 2) 逆順
sort -r file

# 3) 数値としてソート（"10" が "2" より後になる）
sort -n numbers.txt

# 4) 人間向け単位（K/M/G）でソート（du/df/ls -h の出力に便利）
sort -h sizes.txt

# 5) バージョンっぽい文字列をソート（1.9 < 1.10 を正しく）
sort -V versions.txt

# 6) 重複を落としてユニーク化（並べ替えもされる）
sort -u file

# 7) 頻度集計（多い順）
# よくある: "どのIPが多い？" "どのエラーが多い？"
cat access.log | awk '{print $1}' | sort | uniq -c | sort -nr | head

# 8) すでにソート済みかをチェック（CIや検証に便利）
sort -C file || echo 'NOT SORTED'

# 9) CSV の2列目をキーにソート（"," 区切り、2列目で比較）
# -t: 区切り, -k: キー（2列目の先頭〜2列目の末尾）
sort -t, -k2,2 file.csv

# 10) 文字コード/locale の影響を避けて“バイト順”に（運用の定番）
LC_ALL=C sort file
```

## SYNOPSIS（書式）

```text
sort [OPTION]... [FILE]...
sort [OPTION]... --files0-from=F
```

- `FILE` を省略、または `-` を指定すると標準入力から読む
- `--files0-from=F` は「NUL 区切りでファイル一覧を渡す」モード（大量ファイルや変な名前対応）

## sort の基本（比較のされ方）

`info '(coreutils) sort invocation'` の説明の要点：

- `sort` は **キー（`-k`）で比較**して差がつくまで順に比べる
- キー指定が無ければ「行全体」がキー
- 最後に“最後の手段”として **行全体を比較**して順序を決めることがある
  - `--stable`（`-s`）はこの“最後の手段”比較を無効化し、キーが同一なら入力順を保つ
  - `--unique`（`-u`）も“最後の手段”比較を無効化する

### locale（環境変数）で順序が変わる（超重要）

`sort` はデフォルトで `LC_COLLATE` の規則に従います。
運用で「思った順番と違う」ときは、まずこれを疑います。

```bash
# 伝統的（バイト値）の順序でソートしたいとき
LC_ALL=C sort file

# たとえば /etc の設定名やログの固定順序をスクリプトで扱うときは
# LC_ALL=C を付けるのが事故りにくい
```

## 操作モード（sort / merge / check）

- デフォルト：ソートして出力
- `-m`, `--merge`：各入力ファイルが **個別にソート済み** である前提で高速マージ
- `-c` / `-C`：ソート済みかチェック

```bash
# ソート済みチェック（乱れていたら先頭の乱れを診断して exit 1）
sort -c file

# ソート済みチェック（静かに exit status だけ欲しい）
sort -C file

# マージ（入力はそれぞれ sort 済みであること）
sort -m a.sorted b.sorted > merged.sorted
```

## キー指定（-k）と区切り（-t）

### `-t`（区切り）

- `-t,` のように「1文字」を区切りにできる（CSVなら `,`）

### `-k F[.C][,F[.C]]`（キー範囲）

- `F` はフィールド番号（1始まり）
- `C` はフィールド内の文字位置（1始まり）
- `-k2,2` は「2フィールドだけ」をキーにする定番

```bash
# 2列目だけで比較
sort -t, -k2,2 file.csv

# 1列目→2列目の優先順で比較（多段キー）
sort -t, -k1,1 -k2,2 file.csv

# 数値キーとして扱う（2列目を数値に）
sort -t, -k2,2n file.tsv
```

コツ：キー指定が合っているか怪しいときは `--debug` が便利です。

```bash
sort --debug -t, -k2,2 file.csv
```

## よく使う並べ替えオプション

- `-n`：数値として比較（整数っぽいもの向け）
- `-g`：一般数値（浮動小数/NaN等も考慮、遅いので必要時だけ）
- `-h`：K/M/G などの単位付き数値（`du -h` の出力に便利）
- `-V`：バージョンソート（`1.9` と `1.10`）
- `-f`：大文字小文字無視
- `-b`：キーの先頭にある空白を無視
- `-u`：重複を抑止（先頭の1行だけ残す）

注意：`-u` は「完全一致の重複」だけ落とします。
「特定列だけ見てユニーク」したい場合は `-k` もセットで考えます。

## 大きいファイルの実務オプション

- `-T DIR` / `--temporary-directory=DIR`：一時ファイルの置き場所
- `-S SIZE` / `--buffer-size=SIZE`：メモリ使用量の目安
- `--parallel=N`：並列度
- `-o FILE`：結果をファイルへ（標準出力に流さない）

```bash
# /tmp が小さい/遅い環境で一時領域を変える
sort -T /var/tmp big.log > big.sorted
```

## NUL 区切り（変なファイル名対策）

- `-z`：入力の区切りを改行ではなく NUL（`
` ではなく `\0`）として扱う
- `--files0-from=F`：NUL区切りのファイル一覧を読む

（ファイル名に空白や改行が混ざる世界に対応するための仕組みです）

## 終了コード（coreutils sort）

`info '(coreutils) sort invocation'` に明記があります。

- `0`：エラー無し
- `1`：`-c` または `-C` 指定で、入力がソート済みではない
- `2`：エラー

## 事故りポイント（sort あるある）

- locale の影響で順序がズレる → 迷ったら `LC_ALL=C sort`
- `-k` の範囲指定が意図とズレる → `-k2,2` を基本形にして `--debug` で確認
- `-n` を付け忘れて文字列比較になる（`10` が `2` より前/後で混乱）
- `sort -u` と `uniq` を混同する（`uniq` は隣接だけ、`sort -u` は非隣接もまとめて消せる）
