# kill(1) — プロセスへシグナルを送る（止める・合図する）

`kill` は「プロセスを殺すコマンド」というより、**プロセス（またはプロセスグループ）にシグナルを送るコマンド**です。

- 何も指定しないと `TERM`（= `SIGTERM`, 通常15 / 終了要求）を送る
- ダメなら `KILL`（= `SIGKILL`, 9 / 強制終了）を使う

`KILL`（9）は捕捉できず後始末もできないので、通常は **TERM →（待つ）→ KILL** の順が安全です。

## SYNOPSIS（書式：manより要点）

```sh
kill [-signal|-s signal|-p] [-q value] [-a] [--timeout milliseconds signal] [--] pid|name...
kill -l [number] | -L
```

## まず結論：よく使うコマンド（運用）

```sh
# まずは丁寧に止める（デフォルトは TERM）
kill 12345

# 名前で止める（同名プロセス全体に飛ぶので注意）
kill nginx

# 最終手段（強制終了）
kill -KILL 12345
# or
kill -9 12345

# 生存確認（シグナルは送らない。存在/権限だけチェック）
kill -0 12345

# シグナル一覧
kill -l

# シグナル番号→名前（例：15→TERM）
kill -l 15
```

## 通常終了（SIGTERM）と強制終了（SIGKILL）は必ず書く

運用では、まずこの2つをセットで覚えると事故が減ります。

- `SIGTERM`（通常 `15` / `TERM`）: **通常終了**（後始末のチャンスを与える）
- `SIGKILL`（`9` / `KILL`）: **強制終了**（捕捉不可・後始末不可）

書き方は名前指定が読みやすいです。

```sh
# 通常終了（まずはこれ）
kill -TERM 12345

# 強制終了（最終手段）
kill -KILL 12345
```

番号で書く流儀もあります（`kill -15` / `kill -9`）が、
人間がレビューする運用ノートでは `-TERM` / `-KILL` の方が意図が伝わりやすいです。

## 重要：`TERM` と `KILL` の違い（ここだけは覚える）

- `TERM`（通常 15）
  - 「終了してください」という要求
  - プロセスはハンドラで後始末（ファイル削除、ロック解放など）して終了できる
  - **基本はこれを使う**

- `KILL`（9）
  - 即時に強制終了
  - 捕捉できず、後始末する機会を与えない
  - **TERMで止まらないときの最終手段**

運用の型：

```sh
kill 12345
sleep 2
kill -0 12345 || echo "stopped"

# まだ生きていたら最終手段
kill -KILL 12345
```

## 引数（pid の特殊値が危険）

`pid` には数字以外に特殊値があり、範囲が大きいので要注意です。

- `0` : **現在のプロセスグループ**の全プロセスに送る
- `-1` : PID 1 より大きい **ほぼ全プロセス**に送る（超危険）
- `-n` : プロセスグループ `n` に送る

特に `-n` は「シグナル指定」と見分けがつかないため、man にある通り
**プロセスグループを指定したいときは `--` を挟む**のが安全です。

```sh
# 例：PGID 1234 に TERM を送りたい
kill -TERM -- -1234

# これだと "-1234" をシグナル番号と誤解され得る
# kill -TERM -1234
```

## `name` 指定の注意（巻き込みやすい）

`kill name` は「その名前で起動されたプロセス全部」に送ります。

- 誤って巻き込みやすい（同名が複数ある）
- 期待のプロセスだけ止めたいなら PID 指定が安全

PID を拾う導線（例）：

```sh
ps -ef | grep name
ss -ltnp
systemctl status service
```

## `--timeout`（段階的に止める）

man の例のように、シグナルを段階的に送り、間隔を空ける指定ができます。

```sh
# 例：QUIT →（1秒待つ）→ TERM →（1秒待つ）→ KILL
kill --signal QUIT --timeout 1000 TERM --timeout 1000 KILL 12345
```

運用での意図は「丁寧に止めたいが、いつまでも待たない」です。

## 終了ステータス（スクリプトで見る）

man より：

- `0` : 成功
- `1` : 失敗
- `64` : 一部成功（複数プロセス指定時など）

## シェルのビルトイン vs /bin/kill（混乱ポイント）

多くのシェルは `kill` ビルトインを持ち、通常はそちらが優先されます。
`--timeout` や `name` 指定などは実装差が出ることがあるので、
「manにあるのに効かない」場合はまずここを疑います。

確認：

```sh
type kill

# util-linux の kill(1) 実体を使いたい場合
/bin/kill --version
```

## systemd 管理下のプロセスを止めるとき

サービス（daemon）なら、まずは `systemctl stop`/`restart` を優先します。
`kill` で止めると、

- 自動再起動ポリシーで戻る
- 状態がズレる

などが起きることがあります。
