# sed(1) — stream editor（ストリーム編集）

`sed` は「入力（ファイル/標準入力）を1行ずつ読み、ルールに従って書き換えて出力する」ためのコマンドです。
運用では、ログや設定の**ちょい変換**（置換/抽出/削除/整形）をパイプでつなぐときに刺さります。

- `grep` が「探す」
- `sed` は「変える/抜く」

このノートは `man sed` と `info sed` を土台に、**運用でコピペしやすい形**（`-n`、`s///`、範囲指定、`-i`、終了コード、事故りポイント）でまとめます。

## まず結論：よく使うコマンド

```bash
# 1) 置換（最頻出）：最初の1回だけ置換
sed 's/old/new/' file

# 2) 置換（全置換）：行内のマッチを全部置換
sed 's/old/new/g' file

# 3) 正規表現を使うなら -E（ERE）を明示（読みやすい）
sed -E 's/(foo|bar)/X/g' file

# 4) マッチした行だけ表示（grepの代わりにもなる）
# -n: 自動表示を止める, /pat/p: patに一致した行だけ print
sed -n '/ERROR/p' /var/log/messages

# 5) 空行を削除（空行除去）
sed '/^$/d' file

# 6) 先頭の # コメント行を消す（空白+ # も含む）
sed -E '/^[[:space:]]*#/d' file

# 7) 前後の空白を削る（両端トリム）
# 先頭: s/^[[:space:]]+//, 末尾: s/[[:space:]]+$//
sed -E 's/^[[:space:]]+//; s/[[:space:]]+$//' file

# 8) 範囲で抜く（BEGIN〜END の間だけ）
sed -n '/^BEGIN$/,/^END$/p' file

# 9) 置換してファイルを書き換える（in-place）※慎重に
# バックアップを作ってから編集するのが無難
sed -i.bak 's/PermitRootLogin yes/PermitRootLogin no/' /etc/ssh/sshd_config

# 10) 複数ルールは -e を複数回、または ; で連結
sed -e 's/foo/bar/g' -e 's/baz/qux/g' file
# 同等
sed 's/foo/bar/g; s/baz/qux/g' file
```

## SYNOPSIS（書式）

```text
sed [OPTION]... {script-only-if-no-other-script} [input-file]...
```

- `input-file` を省略すると標準入力を読む（パイプで使える）
- `-e script`：スクリプト（編集ルール）を追加（複数可）
- `-f script-file`：スクリプトファイルを読む

## sed の超ざっくり動作（ここが分かると事故りにくい）

`sed` は基本的に次のサイクルで動きます。

1. 1行（またはパターンスペース）を読み込む
2. スクリプト（ルール）を上から適用する
3. デフォルトで、その結果を出力する（**自動表示**）
4. 次の行へ

重要：`-n` を付けると **3 の自動表示が止まる** ので、`p`（print）で出したい行だけ出す、という設計になります。

- `sed 's/a/b/' file` → 全行出力（置換が無い行もそのまま出る）
- `sed -n 's/a/b/p' file` → 置換が起きた行だけ出力（`p` フラグ）

## 正規表現（BRE/ERE）と `-E`

`sed` の正規表現はデフォルトで **BRE**（Basic Regular Expressions）です。
運用では `+` や `()` を使いたくなることが多いので、**`-E` を付けて ERE にする**のが読みやすくて安全です。

- BRE（デフォルト）
  - `+` `?` `|` `()` はそのままだとメタ文字ではない（環境差/混乱の元）
- ERE（`-E`）
  - `+` `?` `|` `()` がメタ文字になり直感的

```bash
# ERE で「数字が1回以上」
sed -E 's/[0-9]+/NUM/g' file

# BRE で同じことをやると、+ をメタ扱いにするため \+ が必要になりがち
sed 's/[0-9]\+/NUM/g' file
```

### クォート（シェル展開事故を防ぐ）

基本は **シングルクォート**で囲います：`'s/.../.../'`。
クォートしないと `*` や `?`、`$` などがシェルに解釈されて事故りやすいです。

### 区切り文字は `/` 以外も使える

`/` が多いパス置換は、区切り文字を変えると読みやすいです。

```bash
# / を多用するので | 区切りにする
sed 's|/var/www/html|/srv/www|g' file
```

### 置換側でよく使う記号：`&` と `\1`

- `&`：マッチした全体
- `\1` `\2` ...：キャプチャ（丸括弧で取った部分）

```bash
# 例: 末尾に .bak を付ける（マッチ全体を & で参照）
echo 'foo' | sed 's/.*/&.bak/'

# 例: key=value の value だけを括弧で取り、置換で参照
# (.*) を \1 で参照（-E 推奨）
echo 'PORT=8080' | sed -E 's/^([A-Z_]+)=(.*)$/name=\1 value=\2/'
```

## アドレス指定（どの行に適用するか）

`sed` は「全行に適用」だけでなく、**特定の行/範囲**にだけルールを適用できます。

### 1行だけ（行番号）

```bash
# 1行目だけ表示
sed -n '1p' file

# 10行目を削除
sed '10d' file
```

### マッチした行（正規表現）

```bash
# ERROR を含む行だけ表示
sed -n '/ERROR/p' a.log

# DEBUG 行を削除
sed '/DEBUG/d' app.log
```

### 範囲（addr1,addr2）

```bash
# BEGIN〜END の範囲を表示（行自体も含む）
sed -n '/^BEGIN$/,/^END$/p' file

# 3〜5行目を削除
sed '3,5d' file
```

### GNU sed の特殊な範囲指定（覚えておくと便利）

`man sed` にある GNU 拡張の2アドレス形式です。

- `0,addr2`
  - 1行目の前（0）から `addr2` が見つかるまで、のような扱い
  - `addr2` が1行目にマッチする場合の挙動が `1,addr2` と異なる
- `addr1,+N`
  - `addr1` にマッチした行と、その**後ろN行**
- `addr1,~N`
  - `addr1` にマッチした行から、行番号が N の倍数になる行まで

```bash
# 「ERROR が出た行」＋その後ろ5行を表示
sed -n '/ERROR/,+5p' app.log
```

## よく使う編集（コピペ用）

### 置換 `s/REGEXP/REPL/FLAGS`

- `g`：行内のマッチを全部
- `p`：置換が起きたらその行を表示（`-n` とセットで便利）

```bash
# 置換が起きた行だけ見たい
sed -n 's/timeout=\([0-9]\+\)/timeout=30/p' file

# ERE で書くならこう（読みやすい）
sed -n -E 's/timeout=([0-9]+)/timeout=30/p' file
```

### 削除 `d`（ノイズ除去の基本）

```bash
# 空行とコメントを消す（設定のざっくり正規化）
sed -E '/^$/d; /^[[:space:]]*#/d' file
```

### 表示 `p` / 行番号 `=`

```bash
# 指定範囲だけ表示
sed -n '100,140p' /var/log/messages

# 行番号を出す（= は行番号を別行に出すので、通常は -n と組み合わせる）
sed -n '/ERROR/{=;p;}' app.log
```

### 複数行を扱う：`N`（必要なときだけ）

改行をまたぐ処理はやや難しくなります。まずは「どうしても必要」なときにだけ。

```bash
# 例: 連続する空行を1つに潰す（単純な整形）
# （挙動が分かりづらいので、必要ならこの例から開始）
sed -E ':a; N; s/\n{3,}/\n\n/; ta' file
```

## `-i`（in-place編集）運用の注意

`-i` はファイルを直接書き換えます。
運用では **必ずバックアップ拡張子を付ける**のが無難です。

```bash
# .bak を作りつつ編集
sed -i.bak 's/old/new/g' file

# 拡張子無しは「戻せない」ので本番運用では慎重に
sed -i 's/old/new/g' file
```

注意ポイント：

- 対象が複数ファイルだと、全部が一気に書き換わる
- 正規表現が雑だと意図しない場所まで置換する
- まずは `sed ... file > /tmp/out` で差分確認してから `-i` が安全

## 終了コード（Rocky Linux 9.7 / GNU sed）

`info sed` の *Exit status* にある通り、GNU sed は次を返します。

- `0`：成功
- `1`：不正なコマンド/文法/正規表現、または `--posix` と併用できない GNU 拡張
- `2`：入力ファイルの一部が開けない（処理は他ファイルで継続）
- `4`：I/O エラーや深刻な実行時エラーで中断

また、GNU 拡張として `q [exit-code]` / `Q [exit-code]` で任意の終了コードを返せます。

## 事故りポイント（sed あるある）

- `-n` を付けたのに `p` を書き忘れて「何も出ない」
- 正規表現の `+` や `()` を使っているのに `-E` を付け忘れてハマる
- パス置換で `/` が多くて読めない（区切り文字を `|` などに変える）
- `-i` で本番ファイルを一撃で壊す（まずバックアップ、可能なら差分確認）
- `&`（マッチ全体）や `\1`（キャプチャ）を置換側で使うときにエスケープを間違える
