# id(1) — ユーザー/グループID（real/effective）を確認する

`id` は「ユーザーID（UID）とグループID（GID）、所属グループ」を表示するコマンドです。

運用で効くのは次の用途です。

- 「このプロセス/セッションは **誰として動いている**？」（権限不足の切り分け）
- 「**所属グループ**に入っている？」（ファイルやソケットのアクセス権）
- 「SELinux の **context** は？」（`-Z`）

## まず結論：よく使うコマンド

```bash
# 1) 今の自分（よくある確認）
id

# 2) あるユーザーの情報
id nginx

# 3) 実効UID / 実UID（sudoやsetuid絡みの切り分け）
id -u
id -ru

# 4) 実効GID / 実GID
id -g
id -rg

# 5) 所属グループ（数値）/（名前）
id -G
id -Gn

# 6) UID/GID/Groups を「名前」で
id -un
id -gn

# 7) SELinux context だけ
id -Z

# 8) 複数ユーザーを一気に
id root nginx tama
```

## SYNOPSIS（書式）

```text
id [OPTION]... [USER]...
```

- `USER` を省略すると現在ユーザー
- `USER` を複数指定すると、それぞれ表示

## 出力の読み方（まずここ）

`id`（オプション無し）の典型的な出力イメージ：

```text
uid=1000(tama) gid=1000(tama) groups=1000(tama),10(wheel)
```

意味：

- `uid=`: **実効UID（effective uid）** とそのユーザー名
- `gid=`: **実効GID（effective gid）** とそのグループ名
- `groups=`: **所属グループ一覧**

※ 表示される細部は環境で変わることがありますが、読み方の軸は同じです。

## real（実）と effective（実効）の違い

`id` は「実（real）」と「実効（effective）」を区別できます。

- **実UID/GID（real）**: もともとのログインユーザーのID
- **実効UID/GID（effective）**: いま権限チェックに使われるID（その瞬間の“権限”）

運用のよくある場面：

- `sudo` で root 相当の操作をしている
- setuid/setgid された実行ファイルで権限が切り替わっている

確認の型：

```bash
# 実効UID（いまの権限）
id -u

# 実UID（元のユーザー）
id -ru
```

同様にGIDも `-g` / `-rg` で確認します。

## よく使うオプション

### UID/GIDだけ欲しい：`-u` / `-g`

```bash
id -u
id -g
```

- シェルスクリプトで「数値だけ」が欲しいときに便利です

### real を見たい：`-r`

`-r` は `-u/-g/-G` と組み合わせて意味を持ちます。

```bash
id -ru   # 実UID
id -rg   # 実GID
```

### グループ一覧：`-G` と `-n`

```bash
id -G    # グループID（数値）
id -Gn   # グループ名
```

`-n` は「数値ではなく名前で出す」指定で、`-u/-g/-G` とセットで使います。

### SELinux context：`-Z`

```bash
id -Z
```

SELinux 有効環境では、
「どのユーザー/ドメインのコンテキストで動いているか」がアクセス可否に直結することがあります。

`ls -Z`（ファイル側のコンテキスト）と組み合わせて見ると切り分けが早いです。

## スクリプト向け（区切りの罠を避ける）：`-z`

`id` の結果を機械処理する場合、空白で分割するのは危険です（想定外の区切りが混ざる可能性）。

`-z` を付けると「空白ではなく NUL 区切り」で出せます。

```bash
# NUL 区切り（デフォルト出力形式では使えない制約があるので注意）
id -z -Gn
```

NUL 区切りは `xargs -0` などと相性が良いですが、
ツール側が対応していないと扱いづらいので、必要なときだけ使うのが無難です。

## 典型トラブルの切り分け例

### 例1：権限不足（Permission denied）

「本当にそのユーザー/グループで作業しているか？」をまず確認します。

```bash
id
id -Gn
```

- 期待するグループ（例: `wheel` やアプリ用グループ）に入っていない
- `sudo -i` してるつもりが実効UIDが変わっていない

などがすぐ分かります。

### 例2：SELinux が怪しい

```bash
id -Z
ls -lZ /path/to/file
```

「プロセス側（自分の context）」と「ファイル側（対象の context）」を揃えて観察します。

## 事故りポイント

- **`-n` を単独で使っても意味がない**
  - `-n` は `-u/-g/-G` とセット（例: `id -un`, `id -Gn`）
- **real/effective を混同する**
  - いまの権限は `id -u`、元のユーザーは `id -ru`
- **グループ未所属を見落とす**
  - `id -Gn` で「所属グループ名」を必ず見る

## 参考（man から）

- `id` は「指定ユーザー（省略時は自分）の user/group 情報を表示」
- `-Z` で SELinux context のみ
- `-u/-g/-G` はそれぞれ UID/GID/全グループ
- `-r` は real を表示（`-u/-g/-G` と併用）
- `-n` は数値ではなく名前を表示（`-u/-g/-G` と併用）
